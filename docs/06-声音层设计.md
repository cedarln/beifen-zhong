# 声音层设计（v0.1）

前提一句话：**我们不做"跟随剧情起伏的背景音乐"，我们做"跟随剧情起伏的环境音量"。**
小满住在手机缓存里，她那儿唯一该有的声音是楼里的声音——水管、工频、日光灯、电梯钢索。
情绪不靠旋律推，靠**安静被打破**推。这是《生命线》那类作品的真实做法，也是圣经规则 9
（不许写她哭）在听觉上的对应物：不许有配乐替玩家难过。

---

## 一、四条声床（全部本机 ffmpeg 程序化合成，零版权）

生成脚本：`tools/gen_ambience.sh`；检验脚本：`tools/check_ambience.py`。
产物在 `android/app/src/main/res/raw/`，4 条基准声床 + 1 条劣化轻档，合计 **4.12 MB**
（16bit/mono/16kHz PCM，每条 27.000s）。

| 声床名 | 文件 | 它是什么 | 什么时候响 |
|---|---|---|---|
| `bed_room` | bed_room.wav | 房间底噪（两路独立噪声各压低通，生成时立体声、交付拍单声道） | 全程的基础层。它退后＝她不在自己屋里 |
| `hum_mains` | hum_mains.wav | 50Hz 工频 + 150Hz 谐波 + 极细高频闪噪（日光灯） | 楼在"运转"时；D3 唯一超自然错觉的顶点 |
| `detail_drip` | detail_drip.wav | 稀疏水滴 + 瓷砖房间短回声 | 具体名词的声音。D5 车库、灭屏信 |
| `anomaly_bitcrush` | anomaly_bitcrush.wav | 降采样保持 + 随机门控结巴 | **它就是清除进度的听觉形式**，随 integrity 单调上升 |
| `anomaly_bitcrush`（轻档） | anomaly_bitcrush_lite.wav | 同一条素材，只走 14k 那条链、门控压浅 | integrity ≥ 55 时引擎播这条；< 55 换成上面那条 |

为什么程序化合成而不是找素材（除版权与体积外的真实理由）：
`anomaly` 必须是**同一个文件的不同降采样链**，不是"一段更破的循环"。玩家听到的劣化
和她在被清除的进度是同一个数，不是两件事。素材库给不了这个。

**为什么成品是无损 PCM 而不是 ogg/mp3**（这条是被实测逼出来的，不是洁癖）：
`hum_mains` 是有相位的 50Hz 正弦。任何有损编码器在循环点的 priming gap 上都会把它
切成一个台阶——那正好毁掉最不该出戏的一条声床。PCM 让引擎可以**按样本**接管循环点：
`AudioTrack(MODE_STATIC)` + `setLoopPoints(loopStart, loopEnd)`，硬件级回到第 432000 个
样本而不是"近似那里"。4.1 MB 换的是确定性，值得。

合成与归一化时已处理的四件事，改脚本别改回去：

1. **无缝循环用正解**：`out = acrossfade(S[X:T], S[0:X])`，成品 27s。反过来写（把尾部淡进头部）
   对纯噪声碰巧听不出来，对 50Hz 这种有相位的内容会在循环点"咔"。
2. **门控与起伏的周期整除 27s**：`2/27`、`1/27`、`5.4`、`13.5`、`2.7`、`6/27`。不整除会在
   循环点产生慢速泵感。`aecho` 这类带尾音的滤镜会把素材撑长 71ms，所以循环后还要 `atrim` 回整 27s。
3. **全流程一个采样率（16kHz），中间绝不重采样**：重采样器在文件两端用零填充而不是循环邻域，
   接缝在源头就坏了——44.1kHz 版本实测 hum 的接缝跳变是全曲最大跳变的 **15.7 倍**。
4. **响度归一化只用标量增益**：先用 ebur128 测积分响度，再乘一个固定 dB 数推到参考响度。
   弃用 `loudnorm`：它是带包络跟踪和内部 4× 重采样的动态处理，稀疏素材（drip）会被它"泵"起来，
   而且它把重采样伪影正好留在循环点上（实测峰值 −1.3 dBFS，四路一叠就削顶）。
   峰值天花板 −7 dBFS（比 −6 的契约再留 1 dB）优先于响度目标：顶不住就少推一点，宁可差 1 个 LU。

一个必须记住的坑：**ffmpeg 的 ebur128 对立体声文件比对同一内容的 `-ac 1` 单声道结果高 6 dB**。
先测立体声、后出单声道，归一化就会整体偏小 6 dB。所以 `seamless()` 在测之前就 `-ac 1`——
测量对象必须就是交付对象。

实测结果（`python3 tools/check_ambience.py android/app/src/main/res/raw`，全部 PASS）：

| 声床 | 时长 | 峰值 | 积分响度 | 接缝比（全曲最大跳变的几倍） |
|---|---|---|---|---|
| `bed_room` | 27.000s | −9.0 dBFS | −28.0 LUFS | 0.93× |
| `hum_mains` | 27.000s | −21.3 dBFS | −28.0 LUFS | 0.88× |
| `detail_drip` | 27.000s | −10.8 dBFS | −28.0 LUFS | 0.00× |
| `anomaly_bitcrush` | 27.000s | −8.1 dBFS | −28.0 LUFS | 0.38× |
| `anomaly_bitcrush_lite` | 27.000s | −7.0 dBFS | −29.9 LUFS | 0.45× |

噪声源的 `seed` 写死在脚本里，所以这张表可复现；换 seed 等于换素材，要重跑检验并重听。
接缝比 ≤1.5 是硬判据（>1.5 就是"循环点听得出东西"）。44.1kHz 那一版的 hum 是 **15.68×**，
就是被末端重采样毁掉的现场。轻档那条比参考低 1.9 LU 是峰值天花板先顶住了（宁可差 1 个 LU，
不贴边削顶）。统一到 **−28 LUFS** 是剧本侧增益能跨声床比较的前提：段里写 `hum_mains: 0.20`
时，那个 0.20 必须是"相对同一条基准线的 0.20"。

`voice_2014.m4a`（D7 那六秒）目前是 macOS `say` 出的**占位**。正式发行前必须换成真实录音：
她妈妈的口音、先咳一下、录完降采样到 22kHz 让它像 2014 年的手机。**这六秒之前全篇不许出现任何人声**，
所以任何声床、任何提示音都不得有音高轮廓（现在的四条都满足：噪声与单一工频不算旋律）。

## 二、剧本侧契约：编排是数据，不是代码

每章 `meta.ambience`：

```jsonc
"ambience": {
  "beds": ["bed_room", "hum_mains", "detail_drip", "anomaly_bitcrush"],
  "default_gains": { "bed_room": 0.30, "hum_mains": 0.04, "detail_drip": 0.10, "anomaly_bitcrush": 0.02 },
  "fade_ms": 4000,
  "segments": [
    { "from": "d2_n210", "to": "d2_n216b",
      "gain": { "hum_mains": 0.20, "anomaly_bitcrush": 0.12, "bed_room": 0.16 },
      "note": "峰值一：墙里回话" }
  ]
}
```

四条约定，都是硬的：

- **节点级不写 ambience**。一律由章内 `[from, to]` 闭区间决定。理由：逐节点标两百个增益一定写不动，
  而且会把"什么时候变"这个创作判断交给引擎。
- 未列进 `gain` 的声床沿用 `default_gains`；列了的就是覆盖。
- `fade_ms` 限定 600–15000。快于 0.6 秒玩家会听成"切换"而不是"房间变了"。
- **每段必须写 `note`**：说清它为什么变。写不出理由的声床变化就是装饰，校验器不让过。

`tools/validate_script.py` 的 `check_ambience()` 已经在跑这四条，外加一条最要命的：
`d7_n711` 段必须把四条声床**全部归零**，否则 FAIL。全篇唯一人声必须干净。

七章的编排落点（现在已在 JSON 里，共 22 段）：

| 章 | 段数 | 关键落点 |
|---|---|---|
| D1 | 3 | 开场只有底噪不给情绪；`d1_n081` 数 141 遍时工频第一次进来；`d1_n132` 她说出隔壁那句 |
| D2 | 3 | 峰值一（墙里回话）／峰值二（自己收口的册子）／第一封灭屏信只剩水管 |
| D3 | 2 | `d3_n310` 哼鸣顶到全篇最高点，随后立刻回落；灯灭在半路 |
| D4 | 3 | 电闸胶带；念条款念到"这条说的是我"；电梯段把哼鸣**撤干净**只给水管（松弛） |
| D5 | 4 | 车库混凝土；开盒子时四路全退让录音是唯一声源；**灭屏 30 分钟底噪从 0.06 线性推到 0.16**；第二封信劣化第一次超过房间声 |
| D6 | 4 | 公告逐字念出时哼鸣退场；309 峰值劣化 0.55；**11 小时移交中断＝全静音**；假结局声床恢复"正常" |
| D7 | 3 | `d7_n711` 六秒语音＝全归零；"我明天回来再听"底噪回来一点点；第三封信 |

D7 的 `chapter_note` 已写明：这是唯一回暖的一章，`hum_mains` 全章归零，劣化只在结局页之后随 integrity 回来。

两处我特意让它**不出声**的地方，别当 bug 补上：

- `d6_w640..d6_n641` 的 11 小时移交中断＝四路全 0。什么都不放比放什么都可怕。
- `d5_w530..d5_n540` 灭屏 30 分钟只留底噪，而且涨得极慢（30 分钟涨 0.10）。玩家不该意识到声音在变，
  只该在某一刻觉得房间空了。

## 三、引擎侧：AmbienceDirector

输入三样，输出四个增益，全在 UI 线程外做，1.5 秒一次的斜坡：

```
target[bed] = 章内 segment 覆盖值 ?: meta.ambience.default_gains[bed]
target[bed] *= 设备调制系数        // 见下
target[anomaly_bitcrush] += f(integrity)   // 单调：integrity 100→0 映射 0→0.20
```

**设备调制系数**是这一层的真正签名——声音跟着玩家的真实状态走，而不是只跟剧情：

| 信号（已在圣经映射表里） | 调制 | 玩家会怎么解释 |
|---|---|---|
| `screen_off` | 全局 −40% + 低通（`bed_room` 单独 −3dB） | 手机扣在桌上，声音被闷住了 |
| `night_window`（01:00–04:00） | `hum_mains` +40%，`detail_drip` +20% | 夜里水管和电流本来就明显 |
| `battery_low` | 全局 −60%，`hum_mains` → 0 | 它也在省着活 |
| `power_save_on` | 非 `bed_room` 全部 → 0，只留底噪 | 省电模式把"楼"关到只剩一间 |
| `foreground=false` 且 > 90s | 全部 → 0（见第四节） | 它不在的时候是真安静 |

`integrity` 对 `anomaly_bitcrush` 做两件事，都是单调的：**增益** `integrity 100→0` 映射
`0→0.20`，以及**文件选择**——`≥55` 播 `anomaly_bitcrush_lite.wav`，`<55` 播
`anomaly_bitcrush.wav`。切换必须淡到 0 再换，因为一旦"听得出换了"就变成音效，不是环境了。
两条 stem 来自同一条素材的不同降采样链，这就是第二节那句话的兑现：玩家听到的劣化和她被
清除的进度是同一个数。

### 3.5 第一版落地到哪一步（2026-10-27 实现校对）

代码在 `audio/AmbienceDirector.kt`（纯逻辑，JVM 单测 11 条覆盖）与 `audio/AmbiencePlayer.kt`
（AudioTrack 硬件环）。与上面这张表的差异只有两处，都是有意为之，不是遗漏：

1. **`screen_off` 的"低通"第一版没做，只做了增益那两路。** `AudioTrack` 自己不带实时滤波，
   要么挂 `DynamicsProcessing`（API 29+，且它按整条输出处理、会把四条声床一起改变音色），
   要么在软件里重采样——后者违反第二节第 3 条"全流程一个采样率、中间绝不重采样"。
   所以第一版的灭屏＝全局 −40% ＋ `bed_room` 再 −3dB，"闷"这件事暂时只做到"退后"，
   没做到"被捂住了"。真机听一次就能判断这个缺口是否可接受；若要补，方案是 `DynamicsProcessing`
   的 GEQ bands 只在 `screen_off` 期间抬高低频、压低 4k 以上，且必须带 6–15 秒的淡入淡出。
2. **`CONTENT_TYPE_AMBIENT` 用不了**——它在 `@hide` 列表里，公开 SDK 编译不过。
   第一版用 `USAGE_MEDIA + CONTENT_TYPE_MUSIC`。听感上没差别，因为第三节红线 1 早就定了
   **不申请音频焦点、也不注册焦点回调**：不跟任何人抢，就没有"被当成媒体打断"的差别。
   这一条同时写进了 `AmbiencePlayer` 的注释，防止后来者"顺手"把焦点加回来。

另外把两个数对齐一下：表里 `GAIN_CEILING = 0.50` 是**增益上限**（约 −6 dBFS），
红线 3 说的"绝对上限 −12 dBFS"是**合成后的峰值**——stem 素材自身峰值 ≤ −6 dBFS，
再乘 0.50 恰好落在 −12 dBFS 附近。两个说法不矛盾，但分别说的是文件和混音，别混着读。

## 四、四条红线（都是产品决定，不是技术限制）

1. **绝不进铃声/通知通道。** 全部走 `AudioAttributes(USAGE_MEDIA, CONTENT_TYPE_AMBIENT)`，
   不申请音频焦点、不打断来电、被系统抢占就暂停。氛围音不是通知音。
2. **后台一律静音。** 灭屏 >90 秒、或 App 不在前台超过 90 秒（`background_gt_90s`），
   AmbienceDirector 淡到 0 并释放播放器。理由一半是省电，一半是：它不该在她看不见你的时候出声。
   这条同时把"App 在后台偷偷播放"这个最容易被投诉的点从设计上消掉了。
3. **默认关，且第一次启动不响。** 设置项「楼里的声音」默认 off，首次进入章节时以一行小字邀请开启。
   恐怖游戏偷偷放声音是越界，不是沉浸。另外尊重系统媒体音量：绝对增益上限设在 −12 dBFS。
4. **不采集、不联网。** 音频全本地解码，无 Analytics、无远端拉取。剧本层"它只知道这些合法信号"的
   设定不能被音频层出卖——如果玩家觉得"它连我什么时候充电都知道"是因为它真读了通知，
   那我们的隐私红线就白写了。

## 五、验收标准

1. `bash tools/gen_ambience.sh` 在干净环境可重跑（seed 写死，产物逐字节可复现），五个 stem
   全部 27.000s；`python3 tools/check_ambience.py` 退出码 0：格式、峰值 ≤−6 dBFS、
   响度 −28±2 LUFS、接缝比 ≤1.5 全过。总大小按 4.2 MB 预算，不再拿 1 MB 说事。
2. 四条同时以各自 default 增益播放时峰值 < −6 dBFS（不许削波）。
3. 任意章内跳转（后门面板按 node id 传送）后，声床在 ≤ `fade_ms` 内落到目标段，**不得出现"咔"或瞬时起跳**。
4. 走到 `d7_n711` 时四条增益必须实测为 0，误差 < 0.001。
5. 退出到后台 > 90s 后 `dumpsys audio` 看不到本进程的活跃播放轨道。
6. 30 秒内可完全关闭（设置项一键静音），关闭后不残留定时器或播放器实例。

## 六、还没做的三件事（等第一版跑起来再定）

1. **消息到达音**。现在用的是系统 `Notification` 默认音，我倾向自定义一条极短的、和 `detail_drip`
   同源的水管声——但如果它有音高轮廓，就和"不许有旋律"冲突。需要一版试听再定。
2. **"对方正在输入…"要不要声音**。圣经规则 9 靠"长时间正在输入"表现情绪；给它配打字声会把
   最安静的一处变成音效秀。我的倾向是不配。
3. **结局页的静默时长**。《你关掉了我》停在"对方正在输入…"，那之后建议 **完全静音 90 秒**，
   比任何尾声音乐都狠。需要真机试，看玩家会不会以为 App 挂了。
