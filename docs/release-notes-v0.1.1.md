# v0.1.1 · 补丁：让位给系统栏、不再重演历史、给了个更新出处

v0.1.0 发出去之后第一位真机玩家反馈了三件事，这一版把它们都处理了：
**"界面的最上面和最下面分别和通知栏、虚拟键盘重合了，导致按钮按不到。"**
**"你没有做应用更新入口，用户怎么更新应用呢？"**
**"每次重新打开应用都会完整的重新加载一遍之前的所有对话。"**

## 改了什么

1. **贴边（edge-to-edge）让位**。`targetSdk 35` 起 Android 15 强制内容铺满整块屏幕，
   系统忽略 `statusBarColor` / `navigationBarColor`，让位要 App 自己做——v0.1.0 没做。
   现象就是 D1 那三个选项里的第三个压在虚拟键上，等于第一章开局卡死。
   现在 `MainActivity` 显式进入贴边，会话页 / 设置页 / 开发面板三个全屏容器加 `safeDrawingPadding()`
   （它是状态栏、刘海、虚拟键、键盘四者的并集，底部不会叠出两段空白）。
2. **可滚动两页的让位顺序**。设置页与开发面板的 padding 写在 `verticalScroll()` **之前**——
   写在之后也能"看着正常"，但那是把让位塞进了滚动内容里，一往下滚第一行就滑进状态栏。
3. **冷启动不再把历史重演一遍**。会话页的逐条浮现是按剧本节拍走的（她每句话前面还有
   最长 12 秒的"正在输入"，你自己的话之间隔 0.6 秒），v0.1.0 每次重开 App 都会把存档里
   所有历史按这个节拍重新演一次：D1 是半分钟，玩到 D7 就是十几分钟。
   现在引擎在冷启动读盘时记下"这次开机之前她已经说过多少行"，这部分一次性上屏、
   滚动直接落位，只有这一次新说的话才逐条浮现。第一次遇见她的开场动画不受影响。
4. **应用内更新**。设置页「关于这一版」→「检查更新」：查到新版就在应用里下（系统下载器，
   进度在通知栏），下完按『安装』交给系统安装器覆盖安装，**不跳浏览器**。
   代价是本包从这一版起申请 `INTERNET` 与 `REQUEST_INSTALL_PACKAGES`——
   "整包没有网络权限"这句话不能再说了。还能说的是边界，而且它写在代码里、由单测判失败：
   全工程只有 `update/UpdateChecker.kt` 可以碰网络 API，只有设置页能引用它，
   且只在你按下那一颗按钮时动一次——没有启动时自动检查、没有后台轮询，
   引擎与唤醒链路都不引用它。小满的台词仍然一个字都不从网络来（剧本只来自 `script/`）。
   上网的是"你下楼取东西"这件事，不是她能上网。
5. **设置页的版本号改从 `BuildConfig` 取**。v0.1.0 里它是写死的 `v0.1`，
   打补丁时忘了改，玩家看到的永远是旧版本号。

剧本、存档格式、唤醒链路都没动。**覆盖安装即可，进度保留。**（卸载才会真的没有。）

## 为什么 14 条模拟器验收全过却没抓到它

验收用的 AVD 是 android-34，那一版还不强制贴边，而我们也没主动调
`setDecorFitsSystemWindows(false)`——系统替我们让了位。
也就是说"模拟器上看起来是对的"，恰恰是因为它在替我们掩盖问题。
这一版起模拟器上也会复现贴边（我们显式开了），验收清单从 14 条补到 17 条：
第 15 条用 `dumpsys window` 的系统栏 frame 和 `uiautomator dump` 的 bounds 对表，
量到状态栏 `[0,0][1080,128]`、导航条 `[0,2337][1080,2400]`，
修后标题顶 `y=137`、第三个选项文案底 `y=2248`、滚到底时内容不越过 `y=2337`；
第 16 条量冷启动（第 3 秒与第 11 秒各 dump 一次，两次都是 23 行 = 不再逐条重演）；
第 17 条验更新入口（焦点确实切到系统浏览器）。

顺带把第 2 条（崩溃缓冲）的判据改严：缓冲里那 59 行 native crash 属于模拟器自带的
Google 搜索框进程，与本包无关——查崩溃必须 `logcat -b crash -d | grep -c backingup`，得 0。

## 已知没验的

**这条修复本身还没有在真机上复验过**，全部数据来自 arm64 模拟器（android-34）。
你的机器如果不是 Android 15 那一代，行为可能和模拟器一样本来就没问题；
如果是，装 v0.1.1 后请告诉我按钮是否都点得到——这是这份补丁唯一的验收人。

更新入口只验到"链接交给了系统浏览器"：模拟器里的 Chrome 卡在首次运行的欢迎页，
所以"最终落在发布页"这一步没走通；"这台机器没有浏览器时显示兜底文案"那条分支
也没造出场景。这两条留给真机。

其余"没验的"与 v0.1.0 相同（真机后台管控、真的 7 天、一周年、声床现场听感、
6 秒人声节点、无障碍/大字模式），完整清单见 `docs/07` 第四节与 v0.1.0 的发布说明。
