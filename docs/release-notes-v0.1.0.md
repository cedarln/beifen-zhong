# 这版能玩到什么

《正在备份》v0.1.0 —— 离线单机剧情恐怖。307 房间里的人只活在这台手机的本地缓存里，
没有网络、没有服务器、没有账号：她说了几点回来，就几点回来（跨 Doze、跨重启）。

- **7 章（D1–D7），182 个剧本节点，7 个结局**：D6 一个假结局（可回溯）、D7 六个真结局，
  其中《紧急联系人》是隐藏结局（条件写在 `docs/01` 第五节，不在游戏里提示）。
- **主动阅读约 99 分钟，真实等待合计 52 小时**，跨 7 个自然日，单次最长 22 小时。
  等待期间她不说话；到点她会接着说，用的是等待之前那半句话。
- **夜里（23:30–07:30）默认不敲门**：她的话推到早上 07:30 进通知栏，游戏时钟不动。
  想让她照原定夜里时间说，设置页「夜里也让她说」自己打开。
- 楼里的声音（四路声床）默认关，设置页里有一行开关。

装法：下载 `beifen-zhong-v0.1.0-release.apk`，允许"未知来源"后直接装（minSdk 26 / Android 8.0+）。
debug 包（`-debug.apk`）带开发后门（连点标题 5 次，口令 `307`），可以跳章、跳等待、按 node id 传送，
自己玩全流程用它能省 7 天。

# 已经验过什么

自动化（每条都能在干净工作区复现）：

1. `python3 tools/validate_script.py script/act*.json` —— 7 个章文件全部 PASS
   （节点 id 唯一、跳转闭合、signal 全在白名单、等待预算 ±10%、文本硬规则）。
2. `./gradlew --offline :app:testDebugUnitTest` —— **51 条 JVM 单测，0 失败**。
   其中 `ScriptWalkTest` 走通 182/182 节点可达、无孤儿节点；`PlaythroughTest` 验七个结局全部可达；
   `WakeGateTest`（10）验去重与幽灵通知；`QuietHoursTest`（10）验夜间推后；
   `GameClockTest`（7）验倍率与 OFFSET；`AmbienceDirectorTest`（11）验编排段与增益；
   `YearlyTriggerTest`（6）验一周年锚点与 12 条文案池循环。
3. `aapt2 dump badging` 权限清单：无 INTERNET、无通知监听、无无障碍、无通讯录读取；
   主动声明只有 4 条（通知、精确唤醒、忽略电池优化、开机接收）；
   另有四条合并进来的：WorkManager 的 `WAKE_LOCK` / `ACCESS_NETWORK_STATE` / `FOREGROUND_SERVICE`
   与 androidx.core 的自定义签名级 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`
   （Manifest 顶部逐条写了它们干什么）。发布前删掉了一条一直没用过的 `VIBRATE`
   ——代码里从没调用震动，而界面承诺"不响铃、不震动"，留着那条权限就是伪造那句承诺。

真机（这里是 arm64 模拟器 Pixel 6 / Android 14，headless）：

4. release 包 `adb install -r -g` 装得上、起得来，D1 开场到第一个等待全程文案逐条渲染，
   `logcat -b crash` 零行。
5. 唤醒链路按时：排 3 分钟等待 → `dumpsys alarm` 看到 `*walarm*:…/sched.WakeReceiver`，
   到点 `origWhen` 与实际唤醒一致，等待结算、`first_line_after_wait` 出现。
6. **精确唤醒被撤时的降级路径**（本版本新加）：`appops set … SCHEDULE_EXACT_ALARM deny` 后
   仍然挂上 `setAndAllowWhileIdle` 的 RTC_WAKEUP（`flags=0x20`，系统给的窗口 +11 分 14 秒，
   `maxWhenElapsed` = 请求点 +2 分 15 秒），到点唤醒、剧情继续。
   改这行代码之前，这种情况下 AlarmManager 一条闹钟都没有，只剩 WorkManager 兜底。
7. 通知真实投递：授权后 `dumpsys notification` 里出现本包记录，渠道 `corridor`、importance=2
   （不响铃、不震动、不亮屏）。
8. 夜间静默窗口：设备拨到 02:05 让等待到点，`origWhen` 被推到 `07:30:01`，通知栏 0 条，
   前台里下一句照常出现——推后的是通知，不是她那边的时间。
9. **长等待跨重启补投**：走到 D1 那个 2 小时等待（唤醒点被静默窗口推到次日 07:30）后直接 `adb reboot`，
   开机 45 秒后 `dumpsys alarm` 里同一条 `RTC_WAKEUP origWhen=2026-10-28 07:30:00.000` 被重新挂上，
   前台读屏回到「还要等 1小时56分」，本包 crash 零行。
   —— 这一条前两次跑都作废了，因为脚本没真的把界面推进等待状态就去查闹钟；
   `tools/device_wait_reboot_check.py` 现在会自己判"这条验证作废"，比的是唤醒时刻不是闹钟条数。
10. **强制停止之后再回来**：在途等待时 `am force-stop`，`dumpsys alarm` 里本包在途闹钟 1 → 0
    （系统清了闹钟，我们的账本与存档却还在）；冷启动一次，闹钟 0 → 1，唤醒点与强停前完全一致。
    —— 这是发布前自查撞出来的真 bug：旧代码会认为"这条已经排过了"而永不重排，
    覆盖安装更新或玩家在设置里点"强制停止"之后，她就真的再也不来找你了。现在冷启动先销一次账。
11. 声床四路装载与硬件 loop；设置页与后门面板渲染；升级安装（同签名 `install -r`）后进度保留、crash 零行。

逐条命令与输出见 `docs/07-模拟器验收清单.md`。

# 已知没验的

1. **真机与各家 ROM**。全部设备结论来自 arm64 模拟器。国产 ROM 的"自启动/后台管控"
   能把 `setAndAllowWhileIdle` 这条也掐掉；那部分我们没有数据。
2. **真的 7 天**。跨天推进靠 `GameClock` + 单测注入时间 + 模拟器改系统时间，
   没有连续真跑过 7 天；玩家中途改系统时间/关自动时间会看到什么，只推理过。
3. **一周年**。`YearlyTrigger` 的锚点是 10-31 20:14，跨到明年只在单测里造过日期。
4. **听感**。装载、循环点、增益读数验过；"戴上耳机像不像一栋楼"只有耳朵能判。
5. **被系统"智能"杀掉之后**。上面第 10 条修的是"玩家主动强停 + 再打开 App"；
   各家 ROM 后台管控**主动**杀进程时如果没有下一次冷启动，她依然不会敲门。这部分只能等真机数据。
6. **设置页那两行状态（通知开关 / 精确唤醒）只在冷启动读一次**。停着不动去系统设置里改开关，
   这里不会当场变，重开 App 才更新。
7. **大字体 / 无障碍模式**下的排版；**换机**（`allowBackup=false`，换机即从头开始，这是设计）。
8. **D1 第一次等待早于通知授权**。剧本里她要到 `d1_n140` 才开口要"能叫醒你的权利"，
   在那之前（Android 13+ 装机默认关着）到点的那句话只留在游戏里，不会敲门。
   设置页现在会把这台手机的通知现状直接写给你看，但**授权点本身的顺序是剧情，没改**。
9. **7 天里每天真玩一遍**——上面 1、2 两条合起来的实际形态：我们没有像玩家那样过完过一周。
