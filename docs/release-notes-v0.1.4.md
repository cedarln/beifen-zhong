# v0.1.4 · 补丁：度量滑块修好，设置页加了「恢复默认」

玩家报了两件事，第一件是 bug，而且是我们自己看不见的那种。

> 设置里面的度量，调整不回来了。

## 度量滑块为什么是坏的

开发面板第④项那三条滑块，代码长这样：

```kotlin
Slider(
    value = value.toFloat().coerceIn(0f, 100f),
    onValueChange = { onChange(it.toDouble()) },
    …
)
```

看着没问题——**它没写 `valueRange`，而 Material3 的 `Slider` 默认量程是 `0f..1f`。**
于是两件事同时成立：界面上任何 ≥1 的度量都等于"拖到头"（三条全钉在最右端，看着像满值），
而 `onValueChange` 只能回调出 0.0~1.0。玩家拖一下，`trust` 从 62 直接变成 0 或 1，
**并且再也拖不回去**——这就是截图里三条都显示 `1` 的原因。

更难看的是：这个量程本来就已经在数据里声明过了。`BackdoorData.metricRange = 0.0..100.0`
被写在类里，一次都没被用上。所以读代码看不出问题——问题在"少传了一个参数"，
而 Compose 对少传带默认值的参数是不拦的。

现在 `MetricSlider` 显式收量程，并且整步（`steps = 99`）：剧本里的 `needs` 全按整数写
（70、38 这种），不给整步就能拖出 61.7——界面显示 62、闸门按 61 判，是个查不出来的假朋友。

## 顺手修掉的第二个 bug（同一屏，更要紧）

`setMetric()` 改完数值之后是这么重判闸门的：

```kotlin
eng.advance(s, clock, s.nodeId)          // ← 默认 reEmitEntry = true
```

`advance` 的入口节点是**带副作用**的：贴台词、加度量、记 flag。所以拖一下滑块，
她当前那段话就被重新贴进转写一遍、那一笔度量又加一次。`recheck()`（UI 每分钟重问一次
"沉默四小时那条选项出来了没有"）早就踩过并修过了这个坑——`PlaythroughTest` 里那条
"原地重判不许有副作用"就是它。这次是它旁边两个入口漏了：改度量、伪造 signal。
两处都改成 `reEmitEntry = false`。

## 已经被拖坏的进度怎么救

滑块修好之后你能拖回去了（0~100 任意整数）。另外第④项加了一颗
**「回到本章起点」**：按 `act*.json` 里 `meta.start_state` 声明的那组值复位三度量，
不动节点、不动转写、不动你已经走过的分支。

## 设置页新增「恢复默认」

在「关于这一版」下面。它只回滚两件事：**「楼里的声音」关，「夜里也让她说」关**，
外加那行邀请提示下次进章节时重新出现一次。

它明确**不做**四件事，而且这句话就写在按钮旁边、也写在确认框里：
不删存档、不把你退回第一天、不改三度量、不撤你在系统里给过的通知权限（那两样我们撤不掉）。
一颗叫"重置"的按钮如果说不清自己会不会毁掉玩家七天的进度，它就不该存在。
真要重来一次是开发面板里的『清空重开』，玩家侧看不到那颗。

## 为什么这两条现在能被守住

新增 `BackdoorPanelTest`（3 条，源码级判据）。为什么不跑 UI 而是扫源码：
`Slider` 少写一个 `valueRange` 照样编译通过、照样"看起来是个滑块"，
JVM 里没有任何东西能观察到它——这类"少传一个参数就静默错位"的坑，
便宜的守法是把那一行本身变成判据（同一手法已有先例：`NetworkBoundaryTest` 扫网络 API）。

- 度量滑块的 `Slider(` 必须出现 `valueRange`，且量程从 `range.` 取，三处调用点必须真的传了 `data.metricRange`；
- `setMetric` / `resetMetricsToChapterStart` / `overrideSignal` 里的每个 `eng.advance(` 必须带 `reEmitEntry = false`；
- `resetSettings()` 里不许出现 `store.write` / `copyEmpty` / `save.metrics` / `save.transcript` / `save.nodeId`，
  但必须出现 `settings.resetAll()`（不落盘等于重启就被拉回旧值）和 `player.release()`（只翻布尔等于继续偷偷放声音）。

全量单测 **71 条 0 失败**（v0.1.3 是 68 条）。剧本一个字节没动——
两个包的 `assets/act1–7.json` 与 v0.1.3 逐字节一致，我比对过。

## 已知没验的

**这一版还是没上真机、也没上模拟器**（判据全来自 JVM + 编译产物核对）。
要你在设备上看的是两件事：

1. 三条滑块现在**能不能拖到你想要的整数**（整步手感如何——如果拖不准，我把"点数字直接输入"加上）；
2. 「恢复默认」按下去之后，声音是不是真的停了（不是只是开关变灰）。

另外你那份已经被拖成 1 的进度，救法就是上面那颗「回到本章起点」；
如果你更想精确回到某个值（比如 D4 中段 trust 62 / awareness 41 / integrity 55 这种），
告诉我你在哪一章哪个节点、想要哪三个数，我把那组值加进去。
