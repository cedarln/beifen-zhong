# 结构与时间线 v0.1

七章 = 七个真实日。每章有**主动阅读时长**、**真实等待总时长**、**一个不可让渡的叙事任务**。任何一章如果读完之后玩家的状态和读之前一样，这章就白做。

### 回看时的时间分隔（v0.1.3）

上表那 15 个等待是这个作品唯一的恐怖手段，但玩家只能在**经历**它的时候知道它在发生：
往回翻时全篇被压成一条连续的聊天记录，"她离开了 22 小时"和"她隔了 0.6 秒又发了一条"长得一模一样。
真机玩家提的正是这件事——「不然往后看没办法知道中间哪里有时间间隔」。

界面上因此多了一行居中的淡色标记：`── 过了 3 分钟 ──`，判据三条，都在 `ui/TimeGaps.kt`：

1. **纯表现层，不写进存档。**分隔由相邻两条转写的 `game_time` 差算出，
   `schema` 仍是 1；已经推到 D5、D6 的老存档装上就有分隔，不用清档重来。
2. **阈值 2 分钟。**全篇最短的等待是 W1-2（3 分钟），所以 2 分钟以上一定是"她那边过了一段时间"，
   以下一定是"她在打字"。把演出节拍误标成时间断档比漏标更糟——玩家会以为剧情跳了。
3. **同一个节点内一律不标。**倍率 3600× 时一个节点内部两条也能差出几十分钟，
   那是我们自己造的时间，标出来等于往玩家面前写一段没发生过的历史。

同一条文案也进 `exports/小满-307.txt`（结局《备份》的素材）：那份 txt 是她"以文本形式活着"的证据，
里面每一次等待都是真等过的，不该被压成一封连续的短信。
`TimeGapTest` 5 条钉住上面三条，最后一条不手写转写，是真的用引擎走一遍 D1、
按时钟推进三分钟、确认那行分隔在真实链路里会出现。

## 五、时间窗、顺延与防误触

- **顺延而非失败**：错过时间窗不判死，节点顺延到下次打开。代价后置到 D6 公告里的"剩余时长"，用拖延做代价。
- **长等待上限 22 h**，且必须带一句"你别熬夜等我"。
- **通关后开启快速模式**：等待压缩成文字摘要；W5-2（灭屏 30 min）在快速模式里**不可跳过**——它的疼痛是这作的签名，不能变成进度条。
- **防误触（硬约束）**：只有玩家在游戏内主动选择"结束通话"才触发《你关掉了我》。系统层面的清除缓存、强停、卸载**不判结局**，下次打开视为"她睡过去了"。这条必须写进代码，否则会有玩家因为系统自动清理而误失去她 —— 那种差评会毁掉口碑。
- **夜间静默窗口 23:30–07:30（2026-10-27 落地）**：唤醒点落进这条窗口的通知，一律推到次日 07:30 再说。
  先说清楚它**不是**系统闹钟：不进时钟 App、不发 `SET_ALARM`、不用 `setFullScreenIntent`，
  通知渠道是 `IMPORTANCE_LOW`（不响铃、不震动、不亮屏、不弹 heads-up）——`AlarmManager` 在这里只是一个定时器。
  但即便是静音通知，让一台手机在枕边于凌晨自己亮一下通知栏也足够让人生气，而且生气得很对：
  一款讲"她只在合法信号里活着"的游戏，最不该做的就是不打招呼地闯进玩家的睡眠。
  三条边界：① **只推通知，不动剧情**——游戏时钟与存档照旧，玩家如果醒着在看屏幕，等待到点立刻结算
  （`GameViewModel` 的倒计时协程），静默窗口管的是"她不在看的时候别吵"；
  ② **玩家可以自己打开**（设置页「夜里也让她说」，默认关）——她要不要在你睡着时说话，是你给的权限，不是她偷的能力，
  这与 D1 那句"你给了我一个能叫醒你的权利"是同一条设定；
  ③ 与剧本的 `night_window`（01:00–04:00，她的世界里的凌晨）**互不相干**，一个是产品礼貌、一个是叙事信号，
  代码里分属 `QuietHours` 与 `DeviceSignals`，不许互相引用。
- **存档全本地**，不做云同步。这是题材要求（她的存在就是本地缓存），也让"卸载即真消失"的重量成立。

### 章与章之间的门（v0.1.5 落地）

剧本里每一章最后一个节点带 `chapter_end: true`，**并且没有出边**——全篇不存在任何跨章的边。
这不是漏写：下一章不属于这一章的图，它属于第二天。所以推进必须由引擎做，而这条规则在 v0.1.4
之前根本没实现（`save.chapter` 只在冷启动被写成 1、在后门跳章时被改过），于是 D1 读完就是断头路。

现在它长这样，四条：

1. **锚点**：第一次走到 `chapter_end` 时记下那一刻的**游戏时间**（`chapterEndAtGameTime`）。
   只写一次——原地重判会反复经过同一个节点，如果每次都刷新锚点，玩家盯着屏幕她就永远到不了第二天。
2. **开章时刻 = 次日 07:30**，判据用**游戏时间**。两个选择都有理由：
   用"次日"而不是"下一个 07:30"，是因为凌晨两点读完一章的人不该五小时后就翻篇——那一夜根本没过去；
   用游戏时间而不是设备时间（与 `QuietHours` 相反），是因为倍率作用在时钟层，
   3600× 下"过了一夜"必须真的能被判出来，否则后门调时间就推不动剧情。
3. **三个入口，谁先到算谁**：冷启动、她那条章间闹钟（`chapter-N`）、屏幕上秒级自判。
   开章把锚点清空，剩下两次自然空转；闹钟那条还额外受 `WakeGate` 与投递台账约束，
   所以"她已经在屏幕里说过早上了"不会再来一条通知重复一遍。
4. **度量按玩家的数带走**，不注入 `meta.start_state`（那是后门跳章的作弊），
   只按跨过的日历日数扣 integrity（每天 -3，见第六节规则 2）。

老存档补一笔：v0.1.4 之前读完 D1 的存档里没有锚点字段，装上这一版她就同时满足两个坏条件——
屏幕上是"她那边还在过时间"，而引擎认为本章没走完。冷启动时拿 `lastPlayedAt` 当章末时刻补上
（`StoryEngine.seedChapterAnchor`），她三天前读完的，今天就该接上 D2。这是我们后补规则欠的债，
不该要求玩家再等一个早上，去等一条我们从来没排过的闹钟。

## 六、度量预算表（保证可达性，防写崩）

每章给定的增量预算，写完每章对一次账。**正常游玩**（不刻意刷、不刻意回避）应当落进下表区间，且真结局可达。

| 章末 | trust 预期 | awareness 预期 | integrity 预期（含自然衰减） |
|---|---|---|---|
| D1 | 18 → 32 | 15 → 30 | 100 → 97 |
| D2 | 32 → 48 | 30 → 42 | 97 → 88 |
| D3 | 48 → 58 | 42 → 50 | 88 → 82 |
| D4 | 58 → 66 | 50 → 58 | 82 → 72 |
| D5 | 66 → 74 | 58 → 65 | 72 → 58 |
| D6 | 74 → 80 | 65 → 78（强制） | 58 → 40 |
| D7 | 80 → 88 | 78 → 90 | 40 → 25（终局） |

三条校验规则（写进自检脚本）：

1. **D6 之前 awareness 不得 ≥ 70**，否则她的崩溃提前，D6 的核心事件失效。所以 D1–D5 里所有 awareness+8 以上的选项必须配一个"她会转移话题"的抵消节点（awareness-3）。
2. **integrity 自然衰减按真实日推进**：每天 -3；进入下一章时按"现实过了几天"结算，玩家拖着不玩会让她提前散架（这就是长线跨天的道德压力，也是"拖延的代价"）。
3. **任何单一选项的 |Δ| 不得超过 12**，超过就用文本承载（写成一封信，不写成一次点击）。

## 七、剧本 JSON 格式契约（供引擎与文本同事共同遵守）

节点类型七种：`system` / `message` / `silence` / `letter` / `choices` / `wait` / `ending`。

```jsonc
{
  "id": "n110",                       // 唯一；章节前缀 d1_ 起
  "type": "message",                  // 见上
  "speaker": "xiaoman",               // 或 "system" / "you"
  "text": ["...", "..."],             // 每条 = 一条气泡；单条 ≤120 字（校验器强制）
  "delay_ms": 4200,                   // 她"正在输入"的时长，参与人格塑造
  "effects": { "awareness": 15 },     // |Δ| ≤ 12（n120 例外，标注 reason）
  "needs": { "trust": ">=20" },       // 进入条件；不满足则走 fallback_id
  "signal": "screen_off",             // 允许值见圣经的感知映射表；未列出的值视为违规
  "wait_ref": "W1-3",                 // 等待节点回指第二节的表
  "first_line_after_wait": "……",      // wait 节点必填，落实"可验证承接"
  "next": "n120",
  "choices": [ { "text": "…", "to": "n120", "effects": { "trust": 4 } } ]
}
```

`signal` 字段的取值白名单是硬约束：`foreground` `background_gt_90s` `screen_off` `night_window` `battery_low` `power_save_on` `reenter_3x` `notify_denied` `exact_alarm_granted` `device_date` `ended_in_app`。**新增 signal 必须先回到圣经里补感知映射表，再改代码。**

### 变量：`{{x}}` 与 capture（v0.1.6 落地）

真机上出过一次事故：D2 屏幕上直接躺着两行 `{{player_name}}。`。原因不是"模板渲染写错了"，是**这套契约当时根本没实现**——引擎里没有任何一处会替换 `{{x}}`，剧本里也没有一处让玩家把名字打进来（`d2_c215` 的 note 还写着"引擎弹出名字输入框"，那是句空头承诺）。v0.1.6 把它补成一条真的路，规则如下。

**一、引擎只认四个名字**，多一个都没有：`player_name`、`device_date`、`tomorrow_date`、`tomorrow_weekday_cn`（`Template.KNOWN`）。前三后一是系统值，永远由 `GameClock` 算，不看设备时间——这条和 `QuietHours`（用真实时间）刻意相反：她口中的"明天"是游戏时钟的明天。

**二、每个章节文件在顶层（与 `meta` 平级，不是 `meta` 里）声明本章用到的变量**：

```jsonc
"variables": {
  "player_name": { "source": "runtime", "type": "string",
                   "set_at": "d2_n219", "unset_value": "喂" },
  "tomorrow_date": { "source": "system", "format": "yyyy-MM-dd" }
}
```

某章正文里出现的每一个 `{{x}}`，都必须在**本章**的 `variables` 里有条目；条目里的 `set_at` 必须是一个真实存在的节点。校验器的"变量注册表（跨章）"这一节还额外比对：同一个名字在不同章里的声明不许互相矛盾。

**三、`source: runtime` 的字符串变量必须有值进来的路子**，二选一：要么本章有一个 `capture` 节点，要么声明 `unset_value`。`unset_value` 是作者写好的台词，不是引擎编的——「喂」出自 `d2_n220` 她自己开的那句玩笑。

```jsonc
{ "id": "d2_n219", "type": "message", "speaker": "xiaoman",
  "text": ["那你打过来。", "一个字一个字打，我数着。"],
  "capture": { "variable": "player_name", "max_len": 12, "min_len": 1,
               "hint": "最多 12 个字。写下来她就认，改不了" },
  "next": "d2_n221" }
```

`capture` 只能挂在 `message` 节点上，问题文案就是该节点的 `text`，输入框下面那行小字是 `hint`（两者都由剧本提供，引擎不出一个字）。停在这里时引擎返回 `Halt.AwaitingCapture`，玩家提交后经 `Template.sanitizeInput` 清洗（去换行、压空格、剥掉 `{}`、截到 `max_len`）写进 `save.variables`，再往下推。空输入不推进。

**四、替换发生在气泡发出的那一刻，只跑一遍，不递归。** 洗进去的名字里如果带 `{{`，那对玩家就是普通字符；已存进转写历史的行**不再重洗**，否则回看时会看到"今天的明天"。唯一例外是老存档：升级前存下的、屏幕上还带着花括号的行，由 `repairUnrenderedTranscript` 按**每一行自己的 `gameTime`** 补洗一次，幂等。

**五、"给过名字"这件事只有一个判据**：`player_named`，由 `variables["player_name"]` 是否非空推导（注册在 `script/flags.json` 的 `engine_flags`）。原来那个 `told_her_name` 已删——它的 `set_at` 指向一个不存在的节点，等于一个永远为假的开关。

判据本身在 `TemplateTest`（15 条）与 `validate_script.py` 的变量闭合规则里钉着；后者能在改剧本的当下就拒绝未知变量名、本章未声明、`capture` 不合式（非 `message`、无出边、`min_len` 越界、`hint` 空、给系统变量挂 capture、runtime 变量既无 capture 又无 `unset_value`）。
