# 结构与时间线 v0.1

七章 = 七个真实日。每章有**主动阅读时长**、**真实等待总时长**、**一个不可让渡的叙事任务**。任何一章如果读完之后玩家的状态和读之前一样，这章就白做。

---

## 一、七天总表

| 章 | 现实日 | 标题 | 主动阅读 | 真实等待合计 | 本章唯一任务 | 峰值情绪 |
|---|---|---|---|---|---|---|
| 1 | D1 | 醒来 | 12 min | 2 h 20 min | 让玩家相信"这是个真人" | 好奇 + 第一次不适 |
| 2 | D2 | 隔壁的人 | 14 min | 6 h 45 min（夜里她睡着） | 让玩家第一次失去一个东西（305） | 愧疚 |
| 3 | D3 | 走廊 | 11 min | 1 h 30 min + 深夜窗口 | 唯一一次"超自然错觉"（其实全是误读） | 惊吓 → 更冷的松弛 |
| 4 | D4 | 下楼 | 13 min | 4 h | 她第一次不听话（信任出现裂缝） | 失控感 |
| 5 | D5 | 车库 | 15 min | 2 h + 一次 30 min 灭屏 | 记忆断裂：她开始忘记你 | 恐惧（为她，也为自己） |

| 7 | D7 | 面试 | 18 min | 45 min（刻意缩短） | 陪她把那一天过完 | 失去 + 意义的赢 |

主动阅读合计 **99 分钟**（逐章 meta 相加），等待合计约 **50 小时**，真实跨度 7 天。最后把 D7 的等待刻意压到最短——**结局不该让玩家等**，等来的告别是不体面的。

> 这两条在原表里被漏掉了，而它们才是这个结局真正的门槛——引擎现在同时在

## 五、时间窗、顺延与防误触

- **顺延而非失败**：错过时间窗不判死，节点顺延到下次打开。代价后置到 D6 公告里的"剩余时长"，用拖延做代价。
- **长等待上限 22 h**，且必须带一句"你别熬夜等我"。
- **通关后开启快速模式**：等待压缩成文字摘要；W5-2（灭屏 30 min）在快速模式里**不可跳过**——它的疼痛是这作的签名，不能变成进度条。
- **防误触（硬约束）**：只有玩家在游戏内主动选择"结束通话"才触发《你关掉了我》。系统层面的清除缓存、强停、卸载**不判结局**，下次打开视为"她睡过去了"。这条必须写进代码，否则会有玩家因为系统自动清理而误失去她 —— 那种差评会毁掉口碑。
- **夜间静默窗口 23:30–07:30（2026-10-27 落地）**：唤醒点落进这条窗口的通知，一律推到次日 07:30 再说。
  先说清楚它**不是**系统闹钟：不进时钟 App、不发 `SET_ALARM`、不用 `setFullScreenIntent`，
  通知渠道是 `IMPORTANCE_LOW`（不响铃、不震动、不亮屏、不弹 heads-up）——`AlarmManager` 在这里只是一个定时器。
  但即便是静音通知，让一台手机在枕边于凌晨自己亮一下通知栏也足够让人生气，而且生气得很对：
  一款讲"她只在合法信号里活着"的游戏，最不该做的就是不打招呼地闯进玩家的睡眠。
  三条边界：① **只推通知，不动剧情**——游戏时钟与存档照旧，玩家如果醒着在看屏幕，等待到点立刻结算
  （`GameViewModel` 的倒计时协程），静默窗口管的是"她不在看的时候别吵"；
  ② **玩家可以自己打开**（设置页「夜里也让她说」，默认关）——她要不要在你睡着时说话，是你给的权限，不是她偷的能力，
  这与 D1 那句"你给了我一个能叫醒你的权利"是同一条设定；
  ③ 与剧本的 `night_window`（01:00–04:00，她的世界里的凌晨）**互不相干**，一个是产品礼貌、一个是叙事信号，
  代码里分属 `QuietHours` 与 `DeviceSignals`，不许互相引用。
- **存档全本地**，不做云同步。这是题材要求（她的存在就是本地缓存），也让"卸载即真消失"的重量成立。

## 六、度量预算表（保证可达性，防写崩）

| D2 | 32 → 48 | 30 → 42 | 97 → 88 |
| D3 | 48 → 58 | 42 → 50 | 88 → 82 |

## 七、剧本 JSON 格式契约（供引擎与文本同事共同遵守）

节点类型七种：`system` / `message` / `silence` / `letter` / `choices` / `wait` / `ending`。

```jsonc
{
  "id": "n110",                       // 唯一；章节前缀 d1_ 起
  "type": "message",                  // 见上
  "speaker": "xiaoman",               // 或 "system" / "you"
  "text": ["...", "..."],             // 每条 = 一条气泡；单条 ≤120 字（校验器强制）
  "delay_ms": 4200,                   // 她"正在输入"的时长，参与人格塑造
  "effects": { "awareness": 15 },     // |Δ| ≤ 12（n120 例外，标注 reason）
  "needs": { "trust": ">=20" },       // 进入条件；不满足则走 fallback_id
  "signal": "screen_off",             // 允许值见圣经的感知映射表；未列出的值视为违规
  "wait_ref": "W1-3",                 // 等待节点回指第二节的表
  "first_line_after_wait": "……",      // wait 节点必填，落实"可验证承接"
  "next": "n120",
  "choices": [ { "text": "…", "to": "n120", "effects": { "trust": 4 } } ]
}
```

`signal` 字段的取值白名单是硬约束：`foreground` `background_gt_90s` `screen_off` `night_window` `battery_low` `power_save_on` `reenter_3x` `notify_denied` `exact_alarm_granted` `device_date` `ended_in_app`。**新增 signal 必须先回到圣经里补感知映射表，再改代码。**
