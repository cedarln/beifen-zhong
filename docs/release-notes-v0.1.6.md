# v0.1.6 · 补丁：她终于念得出你的名字

真机玩家走到 D2，发来一张截图：屏上两行气泡，内容都是 `{{player_name}}。`。他顺带提了第二句：

> 对话里出现了 player_name 这种占位符，之前的日期 device_date 也是

第一句不是渲染"渲染错了一个字"，第二句也不是格式没对上。**屏幕上一直漏着的是代码原文**——
全篇 6 处占位符（`d1_n120` 两句、`d2_n221`、`d2_n222`、`d5_n500`、`d5_n520`），
这一版之前**一处都没被替换过**。玩到 D5 的人，她跟你说的每一句都带着花括号。

## 一、根因：这条契约从来没实现过

剧本里写 `{{player_name}}` 的时候，脑子里的模型是"引擎渲染时会替换"。检查过代码之后：

1. **`StoryEngine` 里没有任何一处做替换。** 节点文本从 JSON 出来，原样进转写、原样上屏幕。
   `renderer` 这个词在工程里只出现在"渲染 Compose"的意义上。
2. **`player_name` 也没有值进来的路子。** D2 那个选项（`d2_c215` 第三项「我有名字。你拿去用。」）
   直接跳到 `d2_n221`——她那句"那你打过来"根本没被写出来过。存档结构里也没有存变量的字段。
3. **剧本自己的说明是错的。** `d2_c215` 的 note 写着"选此项后引擎弹出名字输入框"，
   act5 的 `variables.player_name.set_in` 指向 `d2_c050`（**这个节点不存在**），
   `flags.json` 里 `told_her_name.set_at` 指向 `d2_c205`（**也不存在**）。
   三处写着"有这一步"，等于三处都没这一步。

所以这不是回归，是缺件。v0.1.5 那条"章与章之间没有门"是同一类毛病：**文档和 note 描述的是设计意图，
不是代码事实**。这一版除了把功能装上，还把它变成能红能绿的判据（第五节）。

## 二、变量渲染：`engine/Template.kt`

引擎只认四个名字，多一个都没有：`player_name`、`device_date`、`tomorrow_date`、`tomorrow_weekday_cn`。
前三后一的规则：

- **替换只发生在气泡发出的那一刻，只跑一遍，不递归。** 玩家在名字框里打 `{{player_name}}`，
  洗掉花括号后她念的是 `player_name` 这几个字——不是把自己的输入再当模板展开一遍。
  这条由 `TemplateTest` 里那条"输入 `{{player_name}}` 当名字"的判据钉着。
- **已存进转写的历史不再重洗。** 回看时不该看到"今天的明天"。
- **日期跟着 `GameClock`，不跟设备时间。** 这和夜间静默窗口（看设备时钟）刻意相反：
  她说"明天"说的是游戏里的次日。3600× 下把时钟推三天，`d1_n120` 那句就从
  "明天是 星期四，2026-10-01。" 变成 "明天是 星期日，2026-10-04。"，测试里两个字符串都写死了。
- **没有值就走剧本给的兜底，永远不返回花括号。** 引擎不发明内容，这条对兜底同样成立。

顺手修掉的那个日期 bug 就是他说的第二句：`d1_n120` 原本写的是
「明天是 `{{tomorrow_weekday_cn}}`，`{{device_date}}`。」——星期几是次日、日期是当天，
玩家看见的是一个**已经过去的日子**。现在多了 `tomorrow_date`，那一行改成引用它。

## 三、名字怎么进来：`capture` 契约

新节点 `d2_n219`（C2 分支，`d2_c215` 第三项现在接这里）：

```jsonc
{ "id": "d2_n219", "type": "message", "speaker": "xiaoman",
  "text": ["那你打过来。", "一个字一个字打，我数着。"],
  "capture": { "variable": "player_name", "max_len": 12, "min_len": 1,
               "hint": "最多 12 个字。写下来她就认，改不了" },
  "next": "d2_n221" }
```

`capture` 只能挂在 `message` 节点上。停在这里时引擎返回 `Halt.AwaitingCapture`，
屏上是她那两句话加一个输入框；输入框下面那行小字取 `hint`。问题文案、字数上限、
提示语**全部来自剧本**——引擎只负责"停住"和"收进来"，它一个字都不写。

提交前后各有一道清洗（`Template.sanitizeInput`）：去换行和制表、连续空格压成一个、
剥掉 `{}`、截到 `max_len`。空输入不推进，她就把这句话留在屏上等。名字存进 `SaveFile.variables`
这个新字段，同签名覆盖安装保留。

"给过名字"这件事只有一个判据：`player_named`，由 `variables["player_name"]` 非空派生，
注册在 `flags.json` 的 `engine_flags`。原先那个 `told_her_name` 已删——它的 `set_at`
指向一个不存在的节点，等于一个永远为假的开关，留着只会误导下一个人。

## 四、没给名字的玩家看到什么

他如果不选「我有名字」，或者选了但一个字都没打就跳章——她不能凭空有个称呼。
剧本里 `d2_n220` 本来就写了这一段（"那我先叫你「喂」"），所以这条路的兜底是**作者已经写好的那句话**：
`variables.player_name.unset_value = "喂"`。D5 她第一句因此是「早，喂。」，
不是「早，」也不是「早，{{player_name}}。」。

只有一处兜底不够用：`d5_n520` 里那句「昨天你跟我说你叫{{player_name}}」——
没给过名字的玩家这里得改口。改口不能靠删句子：删掉以后那一段读起来像漏了一段，
错乱看起来像 bug。所以这个节点带一条 `conditional_line`（`if: player_named == false`），
整段替换成另一套已经写好的十三行，换掉的是「昨天你跟我说你叫…」那两句，
换成「对了，昨天你说你那边今天不下雨。我今天这边也挺好的。」。两条路线在测试里逐行比对过，
防止以后有人改了一条忘了另一条。

## 五、顺带堵上的第二个洞：通知栏里也会漏代码

接线的时候发现，同一批原文有**四条**路根本不经过 `emit`：等待到点的那句承接
（`first_line_after_wait`）、退出后补投的那条（`post_exit_notification.text`）、
次日早上的章间通知（下一章入口第一句）、还有《紧急联系人》周年的那句。
它们进的是 `ReminderScheduler` → 系统通知栏，不进转写，所以只改 `emit` 等于修了一半。
锁屏上挂着一条 `{{player_name}}，早。`，比屏上更糟——那条已经交给系统了，撤不回来。

前台排闹钟那条（`GameViewModel.armWait`）现在按**到点那一刻**渲染：她约的是"明天见"，
用此刻渲染会让"明天是周四"在她真回来那天变成周三。补投那条（`CatchUpWorker`）手里没有
引擎实例，所以渲染口径收到 `Template.varsFor(save.variables, atGameTime)` 一处，
两边共用同一份，不再各拼一遍 `systemVars(...) + variables`。

## 六、把"不许漏到屏幕"变成判据（三层）

**旧存档**也要修：升级前存下的转写里，那些行存的还是带花括号的原文。冷启动时
`repairUnrenderedTranscript` 拿**每一行自己的 `gameTime`** 重算一次再写回（不是拿"今天"算，
否则回看时那句"明天"会被拉到当下），幂等——第二次启动返回 0，不动任何一行。

判据不是靠读代码：

1. `TemplateTest`（16 条，新增）——占位符与本章声明必须闭合、`Template.KNOWN` 里每个名字都要有声明、
   `runtime` 变量必须有 capture 或 `unset_value`、D2+D5 两条路线走完**屏上零个 `{{`**、
   未命名玩家看到「早，喂。」而不是「你跟我说你叫」、清洗与截断、日期跟 `GameClock`、
   通知栏那句与屏上那句逐字相同、老转写补洗幂等。最后一条是**扫源码**的（和
   `NetworkBoundaryTest`、`BackdoorPanelTest` 同一套路）：`CatchUpWorker` 里不许出现
   `ref, text)` / `ref, notice.text)` / `ref, it)` 这三种"把剧本原文直接递给投递口"的写法——
   拿 v0.1.5 那份源码跑一遍这条判据，三种写法命中 4 + 2 + 1 次，它当场就红。
2. `tools/validate_script.py` 新增"变量闭合"与"变量注册表（跨章）"两节——未知变量名、本章未声明、
   capture 挂在非 `message` 节点、capture 节点没有出边、`min_len` 越界、`hint` 空、
   给系统变量挂 capture、`runtime` 变量既无 capture 又无 `unset_value`、同名变量各章兜底值不一致。
   五种坏写法我都逐一试过会 FAIL，不是只写了 PASS 的那一半。
3. `tools/audit_continuity.py` 的 [D] 跨章账本里那一行改到 `player_named`，落点写明 `d5_n500 首句`。

结构侧的回归照旧：`validate_script.py` 七章全 PASS、审计四条线全 OK、
节点数 **182 → 183**（`ScriptWalkTest` 里那个数跟着改了，注释写明多出来的是 `d2_n219`——
这条断言的作用就是"任何增删都要被看见一次"）、
**97 条 JVM 单测 0 失败**（v0.1.5 是 81 条，`--rerun-tasks` 全量重跑）。

## 七、已知没验的

**照旧只跑过 JVM，模拟器与真机都没装过这一版。** 要你在设备上看的是四件事：

1. D2 走到那三个选项，点第三项「我有名字。你拿去用。」——她是不是停在那两句话上、
   **出现一个输入框**（以前这里是直接跳到下一节点，屏幕上给你看代码）；
2. 打完名字之后 D5 早上第一句是不是「早，<你的名字>。」；
3. 走另一条（不选第三项）：D5 第一句是不是「早，喂。」，以及 `d5_n520` 那一段
   是不是换成"昨天你说你那边今天不下雨"那一版、读起来不像缺了一段；
4. **已经中招的那个存档**：装完这一版往回翻，那两行 `{{player_name}}。` 有没有被补成当时的日期和称呼；
5. 把 App 从后台划掉（或直接重启手机），等一条她该敲门的通知到：通知栏那句话里有没有花括号，
   以及它说的是**发出来那天**的日子还是你开机那天的日子。

第 1、2 条只能证明功能在；第 3、4 条是我更想让你看的——那两条路的文案是我照着她的口气补写的，
机器判据管不了"听起来对不对"。哪一句她不会这么说，指到句子上我改那一句。
第 5 条是这一版新写的那条路（`CatchUpWorker` 补投时渲染），单测只能证明"代码里没有那个写法"，
证明不了那条通知真的按时、按对的日子投出来。

另外：输入框在低端机/折叠屏上的实际高度、软键盘弹起时会不会把她那两句话顶出屏幕——
这条和 v0.1.1 那批布局问题同源，模拟器测不了，真机看一眼就知道。
