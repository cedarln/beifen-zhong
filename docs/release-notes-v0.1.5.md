# v0.1.5 · 补丁：她不再把同一句话说三遍，章与章之间有了门

真机玩家发了一张 D1 的截图，四句同样的话连着出现三遍半，并且剧情不动。他问的是：

> 为什么会这样？对方一直重复自己的话，而且没有继续往后推进剧情，是因为我设置了 3600x 吗？

**是两个独立的 bug，而且"不往后推进"和 3600× 一点关系都没有。** 第二个比第一个严重得多：
这一版的剧本从 D1 走到 D2 的路，此前根本不存在。

## 一、重复说话：原地重判把台词又贴了一遍

`StoryEngine.advance(save, clock, 当前节点)` 是"重新判一次闸门"的写法，但它的入口节点**带副作用**：
贴台词、加度量、记 flag。所以只要"当前节点"传进去而没写 `reEmitEntry = false`，
她那段话就被再贴一遍、那一笔度量就被再加一次。

病灶是量出来的。D1 最后那个节点 `d1_n150`（「你去睡吧。」那四句，`chapter_end`，自带 `trust+2`），
在真机同样的路径上原地重判四次，转写条数与 trust 一起往上涨：

| 原地重判 | 转写条数 | trust |
|---|---|---|
| 正常走到章末 | 77 | 42 |
| 第 2 次 | 81 | 44 |
| 第 3 次 | 85 | 46 |
| 第 4 次 | 89 | 48 |
| 杀掉 App 重开，再来 | 93 | 50 |

每多判一次 = **她那四句话多贴一遍 + 那一笔 `trust+2` 多加一次**。截图里的三遍半就是这么来的。
**3600× 不是原因，只是让你更容易撞上它**：倍率越高，你点面板、回前台、重开 App 的次数越多，
而屏上每分钟那次 `recheck()`、后台回前台、冷启动，任何一次原地重判都会 +4 条。
按 1× 慢慢玩同样会中，只是慢得多。

v0.1.4 修过这个坑，但只修了四个入口（改度量、复位度量、伪造 signal、每分钟那次重判）。
**还带着默认 emit 的有六处**：冷启动、闹钟唤醒 `onWake()`、改倍率、跳天数、
`夜间窗口按设备时钟` 那个开关、快速模式开关。截图里之所以是"改一下倍率就多说一遍"，
撞的就是这一类。

这一版不再逐个入口打补丁，改成**一个漏斗**：

```kotlin
private fun StoryEngine.rejudge(save: SaveFile): StoryEngine.Halt =
    openNextChapter(save, clock)                                   // 该开章就先开章
        ?: advance(save, clock, save.nodeId, reEmitEntry = save.nodeId == null)
```

`rejudge` 是"她没往前走，只是重新判了一下闸门"唯一的写法：不重贴台词、不重复扣效果。
`reEmitEntry = save.nodeId == null` 那个条件是必要的——新章节的入口还没演过，
第一次进去必须演；已经是当前节点了就不许再演。

## 二、不往后推进：跨章的门这一版才装上

剧本里每一章最后一个节点带 `chapter_end: true`，**并且没有出边**，全篇也没有任何一条跨章的边。
这不是漏写——下一章不属于这一章的图，它属于第二天（`docs/02` 第一节：七章 = 七个真实日）。
问题是**引擎里从来没实现过"第二天"**：`save.chapter` 只在冷启动被写成 1，
只有后门面板那颗「跳章」会把它改成别的数。

所以玩家正常读完 D1，唯一去处就是屏上那行"这一章到这里。她那边还在过时间。"——
她不会自己进入 D2，等多久都不会。实测：把游戏时钟推满七个真实日，`save.chapter` 仍是 1。

现在的规则（`engine/ChapterGate.kt`，判据全在 `ChapterGateTest` 里）：

1. 第一次走到 `chapter_end` 时记下那一刻的**游戏时间**当锚点，只记一次。
   （原地重判会反复经过同一节点，每经过就刷新的话，玩家盯着屏幕她就永远到不了第二天。）
2. 开章时刻 = **次日早上 07:30**。不是"下一个 07:30"：凌晨两点读完一章的人，
   五小时后不该就翻篇——那一夜根本没过去。判据用游戏时间而不是设备时间（和夜间静默相反），
   因为倍率作用在时钟层，3600× 下"过了一夜"必须真的能被判出来。
3. 三个入口谁先到算谁：冷启动、她那条章间闹钟、屏上的秒级自判。
   开章把锚点清空，另外两次自然空转。
4. **进下一章时三度量按玩家自己的数带走**，只按跨过的日历日扣 integrity（每天 -3）。
   不注入 `meta.start_state`——那是后门跳章的作弊，正常游玩不该把玩家自己攒的信任换掉。
5. 章间闹钟（`ref = chapter-N`）走的是既有那条链路：文案取**下一章入口节点的第一句**
   （引擎不发明内容，通知也不行）、夜间静默照旧、`DeliveryLedger` 去重、重启后 `CatchUpWorker` 补排。

**已经停在 D1 章末的存档**：那些存档里没有锚点字段（v0.1.4 之前根本没有），
装完这一版她就同时满足两个坏条件——屏幕上是"她那边还在过时间"，而引擎认为本章没走完。
冷启动时拿"最后一次游玩"那一刻当章末时刻补上（`seedChapterAnchor`）：
她三天前读完的，今天就该接上 D2。这是我们后补规则欠的债，不该让她再等一个早上，
去等一条我们从来没排过的闹钟。

## 三、顺手修掉的一个隐患：倍率下闹钟会迟到 3600 倍

排闹钟时传的是 `clock.remaining()`——那是**游戏毫秒**。3600× 下"游戏里还有 22 小时"
其实是"真实世界还有 22 秒"，而旧代码排的是 22 小时。App 在前台看不出来
（屏上那个秒级自判会把等待结算掉），只有切后台或锁屏才露头。
新增 `GameClock.deviceDelayUntil()`，`armWait`、重启补排、章间闹钟三处统一改用它。

## 四、为什么 71 条单测全绿却还是让真机撞上了

`PlaythroughTest` 一直是**每章单独开局**跑的（直接 `SaveFile(chapter = N)` 造出来）。
它证明"每一章内部走得完"，却从来没证明过"章和章接得上"。
现在核心那条改成：从 D1 第一句贪心走到最后一个结局，中间不许有人替玩家按跳章——
七个章节、六个夜晚、终点必须落在某个结局节点上。

全量 **81 条 0 失败**（v0.1.4 是 71 条）。剧本一个字节没动。

## 五、已知没验的

**这一版还是只跑过 JVM，没上模拟器、没上真机。** 要你在设备上看的是三件事：

1. 读完 D1 之后：用后门把时间推到第二天早上（或者真的过一夜），
   她是不是自己接上 D2 的第一句，中间**没有**重复台词；
2. 把 App 切到后台、锁屏：早上那条章间通知到不到，文案是不是下一章的第一句；
3. 3600× 下的等待：屏上写"还要等 22 小时"时，真实世界大约 22 秒后就该结算，不是 22 小时。

另外如实说一句：**已经贴进转写的那些重复气泡收不回来**——那是历史，不是 bug 现场，
现在删它等于改玩家的回忆。从这一版起不会再新增。度量坏掉的数可以用后门里那颗
「回到本章起点」复位；如果你更想要"把重复的台词清掉"，我可以加，但那是删存档，
我不想在没人点头的情况下做。
